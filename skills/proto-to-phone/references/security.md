# Security

The prototype is somebody else's code (generated by an AI builder, downloaded, shared). The skill treats it
as untrusted from the first read to the phone.

## On the Mac

| Risk | What the skill does |
|---|---|
| Running prototype code on the Mac | Never. `scan.py` and `adapt.py` read it as text; it runs only in the simulator or on the phone |
| A script picked up from the prototype's folder | Scripts run with `python3 -I` (no current-directory imports); they import only their own folder |
| Writing in the wrong place | Projects only in `~/ProtoPhone/<slug>` or an empty folder; an existing folder that is not a project is refused; `--force` rebuilds only the template parts and keeps the config |
| Bad input reaching a command or a file | Names (1-30 printable characters), team ids, bundle ids, colors and logo files (type, 20 MB cap) are validated; every command is run without a shell |
| Config text breaking out of the page's `<style>` or `<script>` | `</style` and `</script` in config CSS/JS are escaped |
| Inlining files from elsewhere on the disk | `inlineLocalFiles` only reads images and fonts **inside** the prototype's folder (no `../`, no symlinks out), 5 MB each, 30 MB total |
| Installing tools or changing the system | Only after asking; `sudo` commands are handed to the person |
| Leaking identity | Team ids, device ids and the prototype never go into the skill, a repo, an issue or a post |
| Telemetry | None. The scripts talk only to local tools (Xcode, the simulator, the paired iPhone); Apple's servers are contacted by Xcode only for signing, after the person agrees |
| Temporary files | Created in private temporary directories, removed after use |

## In the app

| Area | Rule |
|---|---|
| Files | The page is loaded with read access to its own `Web/` folder only. Navigation to any other `file://` path is cancelled |
| Navigation | The main page cannot navigate away. A link the person taps to `http(s)`, `mailto:` or `tel:` opens outside the app (Safari, Mail, Phone). Navigations started by code (redirects, timers) are cancelled. Other apps' URL schemes are cancelled. Embedded `https` iframes stay inside their frame |
| Network | iOS App Transport Security stays on: `http://` is blocked; no exceptions are added |
| Native bridge | One message handler, two messages: the page background color (three numbers 0-255 and a flag) and "dismiss the keyboard". Any other key or type is ignored |
| Permissions | Camera, photos and microphone are declared (iOS still asks the person). Nothing else |
| Web Inspector | Enabled in debug builds only (the ones this skill makes), so the person can inspect the page from Safari on their Mac |
| Private API | To hide the keyboard's Prev/Next/Done bar, the shell swaps the class of WebKit's internal content view at runtime. Fine for a development build; it would not pass App Review, which is one more reason this is a prototype tool only |
| Data | `localStorage` stays in the app's container on the phone; deleting the app deletes it |

## With Apple

The app is a development build, signed with the person's own team, installed on their own registered device.
The first install registers an app id in their account (a free account allows a limited number per week), so
it needs their explicit OK (`--confirm-device`). Sharing the app with other people needs TestFlight or ad hoc
distribution, which this skill does not do.

## Verified

`tests/` cover the device gates (no build without confirmation and a simulator-checked version), input
validation, escaping and the inlining boundary. The navigation rules were checked in the simulator with a
prototype that tries `file:///etc/hosts`, another app's URL scheme and an automatic redirect: all were
cancelled, and a tapped link opened in Safari.
